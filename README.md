# cowork-courses

需要多人一起写的课程放在这里，一门课一个文件夹。

| 文件夹 | 课程 |
|---|---|
| [`tpu-cluster-handbook/`](tpu-cluster-handbook/) | 万卡级 TPU7x 集群交付参考手册（交付手册 + 讲义 + 经验教训） |

## 怎么参与

1. 维护者把你加为本仓库的 collaborator，并在 [`.github/CODEOWNERS`](.github/CODEOWNERS) 里把你登记到你负责的那门课的文件夹下。
2. 开分支改动，提 PR 到 `main`。
3. CI 会构建每门课、检查站内链接，并跑禁词闸。全绿后，由该文件夹的负责人审核合并。

GitHub 的写权限是按仓库给的，不能只开放某一个文件夹。所以「谁管哪门课」靠 CODEOWNERS 加分支保护落实：
改哪个文件夹，就要那个文件夹的负责人批准才能合并。

## 公开内容的规矩

这是公开仓库，写进来的一切都会被任何人看到：

- 不写合作方名称、内部项目代号、内部链接、真实人名（作者署名除外）。
- 数字写成可公开的口径；拿不准的标 `[推断]` / `[需验证]`。
- CI 的禁词闸用一份不公开的规则表扫描源码和构建产物，命中会报出文件、行号和规则序号，但不会显示规则内容。
  从 fork 提的 PR 拿不到这份规则表，闸门会直接失败，需要维护者在本仓库的分支上重跑。

## 目录约定

每门课一个文件夹，自带 `build.py`，执行 `python3 build.py --check` 后产物输出到该文件夹的 `out/`（不进 git）。
新加一门课时，往上面那张表加一行，再在 CODEOWNERS 里登记负责人。
